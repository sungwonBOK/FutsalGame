최종안: P2P 게임 플레이 + 얇은 연결 서버 + Relay 폴백

1:1에서 바로 시험하고, 이후 5:5에도 같은 메시지 규칙을 유지할 수 있는 구조입니다. 서버는 매 프레임 게임을 계산하지 않습니다.

플레이어 A 클라이언트

  • 입력·이동·카메라·애니메이션 즉시 처리
  • 로컬 히트박스·스킬·공 예측
  • 공격자 판정, 공 발행자 판정
  • 이동/행동/결과를 작게 직송
↔ 직접 P2P
실제 게임 경로
↕ Relay 폴백
전송만 우회

플레이어 B 클라이언트

  • 입력·이동·카메라·애니메이션 즉시 처리
  • 로컬 히트박스·스킬·공 예측
  • 방어·회피 시작을 즉시 전송
  • 최신 이동과 확정 결과만 반영
연결 서버

최소한만 담당

방 생성·상대 매칭·P2P 연결 신호 교환·접속 확인·Relay 이용 정보만 제공합니다. 이동·물리·전투 판정은 하지 않습니다.

Relay

직접 연결 실패 시만

게임 메시지 형식은 그대로 두고 경로만 바꿉니다. 한쪽 PC를 호스트나 중계자로 쓰지 않습니다.

향후 감사 서버

비차단 기록

행동 번호·결과·이상 징후만 복사해 저장합니다. 응답을 기다리지 않으며, 첫 1:1 테스트 범위에서는 구현하지 않습니다.

확장 원칙5:5에서는 각 플레이어가 필요한 상대·팀원에게 직접 같은 네 종류의 메시지를 보냅니다. 어떤 연결이 느려져도 그 대상의 표시만 늦어지고 전체 경기는 멈추지 않습니다. 연결 수나 NAT 문제가 실제 측정에서 커지면, 게임 규칙을 바꾸지 않고 Relay 비중만 높입니다.
