## 프로젝트 소개

**Futsal Brawl**은 공을 지키고 골을 넣는 풋살의 흐름에 공격, 태클, 회피를 더한 3D 액션 풋살 게임입니다.
공을 가진 상태와 그렇지 않은 상태에서 같은 입력이 서로 다른 행동으로 이어지도록 설계해, 공을 빼앗거나 상대의 공격을 피한 뒤 공격 기회를 만드는 심리전을 목표로 합니다.

현재는 핵심 게임플레이와 P2P 멀티플레이를 구현·검증하는 MVP 단계입니다.

## 주요 기능

### 축구 플레이

- 공 획득과 소유권 관리
- 드리블
- 패스 및 차지 패스
- 차지 슛
- 득점, 킥오프, 경기 재시작 흐름

### 격투 액션

- 일반 공격과 강공격
- 슬라이딩 태클
- 회피와 무적 판정
- 공 소유 상태에 따라 달라지는 입력 컨텍스트

### 멀티플레이

- 방 생성·참가 코드 기반의 세션 연결
- 참가자 간 P2P 연결을 위한 신호 교환
- 모든 참가자의 연결 준비 및 `Game ready` 확인 후에만 시작되는 경기 게이트
- 이동, 전투, 공 상태를 동기화하는 P2P 게임플레이 경로를 개발 중

## 조작법

| 입력 | 동작 |
| --- | --- |
| `WASD` / 방향키 | 이동 |
| 마우스 이동 | 카메라 시점 |
| `LMB` | 공 소유 시 패스, 비소유 시 일반 공격 |
| `RMB` | 공 소유 시 차지 슛, 비소유 시 강공격 |
| `Shift` | 스프린트 |
| `Space` | 회피 |
| `F` | 슬라이딩 태클 |

## 개발 과정과 문제 해결

### 공 소유권 변화 중 입력이 다른 행동으로 바뀌는 문제

**문제**<br>
공을 순간적으로 잃은 프레임에 패스 입력이 일반 공격으로 처리될 수 있었습니다. 플레이어 입장에서는 공을 건드린 직후 의도한 패스 대신 공격이 나가는 어색한 경험이었습니다.

**해결**<br>
공의 실제 소유권과 입력을 해석하는 컨텍스트를 분리했습니다. 입력을 누른 시점의 의도를 먼저 고정하고, 짧은 소유권 전환 구간에서는 실제 공 획득을 기다리도록 처리했습니다. 이로써 공의 물리 상태 변화가 곧바로 다른 행동으로 해석되지 않도록 했습니다.

### P2P 멀티플레이의 연결 준비 상태 관리

**문제**<br>
참가자가 방에 들어온 시점과 P2P 연결이 실제로 준비된 시점은 다릅니다. 연결이 완성되기 전에 경기를 시작하면 일부 플레이어에게 이동·전투·공 상태가 전달되지 않을 위험이 있습니다.

**해결**<br>
방과 참가자 정보 관리는 Multiplayer Services 및 Netcode 경로에서 처리하고, 피어 간 연결에는 WebRTC 기반 P2P 신호 교환을 사용했습니다. 모든 참가자의 연결 준비 상태와 `Game ready` 상태를 확인한 뒤에만 호스트가 경기를 시작하도록 게이트를 두었습니다.

## 실행 방법

### 요구 사항

- Unity `6000.5.3f1`

### 실행

1. 저장소를 클론합니다.

   ```bash
   git clone https://github.com/sungwonBOK/FutsalGame.git
   ```

2. Unity Hub에서 클론한 프로젝트 폴더를 엽니다.
3. Unity 패키지 설치가 완료될 때까지 기다립니다.
4. `Assets/_Game/Scenes/SampleScene.unity`를 열고 Play 버튼을 누릅니다.
